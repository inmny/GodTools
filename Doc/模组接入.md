# 模组接入

## 注册天榜

在 GodTools 完成初始化后，在主线程调用 `GodTools.Features.Rankings` 中的接口。注册时可以没有打开世界。数据源的 `Read` 和指标的 `Read` 在刷新时调用。

GodTools 可单独加载，打开排行榜时会检测已加载的模组。模组通过公开接口成功注册分组、来源、字段或榜单后，它的定义优先使用，内置榜单和旧榜关键字自动让位。已加载但未接入的旧版 Cultiway 会使用内置功法榜和人物修仙指标。注册接口可直接识别调用模组。通过共有库或运行时绑定调用时，在定义的 `Owner` 中传入模组自己的 `GetDeclaration()`，供 GodTools 识别归属。

- `RankingRegistry.RegisterSource<T>` 接收 `RankingSource<T>`。提供带模组前缀的 `ID`、`Read`、每行的稳定 `Key` 和 `Name`，可选图标、人物形象、Meta 旗帜、详情、定位或放置回调。`ActorPortrait` 按主键返回当前存活人物，窗口用原版头像控件绘制。`MetaPortrait` 按主键返回当前 Meta 对象，窗口绘制原版旗帜。详情和地图操作收到的是主键，可据此查当前对象。
- `RankingRegistry.RegisterField<T>` 给来源添加字段。用 `RankingValue.Numeric` 表达原始数值，用 `Integer` 注册有序整数字段，用 `Ordinal` 注册品阶，用 `Category` 注册无次序的类别。品阶用 `Options` 登记稳定 ID、名称及顺序，行值用 `RankingValue.Choice` 返回匹配 ID。筛选和榜单记录存储 ID，名称可用本地化键或 `FormatName`。可以通过 `RankingDistributionBand` 把多个细分品阶合并为一个分布桶，细分品阶仍用于排序和筛选。类别按稳定 ID 统计频数。`Sortable` 和 `Operators` 可限制排序和筛选操作，`Version` 用于区分同一字段的规则版本。旧版 `Choice` 和 `Ordered` 注册仍可使用。数值字段可指定 `Unit`，各类字段均可指定 `IconPath` 和悬停 `Description`。引用原版 Meta 对象的字段可指定 `AffiliationType` 并用对象 ID 作为选项键，筛选时会显示原版旗帜。用 `TagSet` 表达一行拥有多个标签。无可用数据时返回 `null`。内置来源 ID 包括 `godtools:actors`、`godtools:items`、`godtools:kingdoms`、`godtools:cities` 和 `godtools:cultures`。给内置来源注册的可排序字段会出现在对应榜单的「排序」中。筛选字段按注册模组分组。通过共有库代注册时，可将 `RankingField<T>.Owner` 设为自己的 `GetDeclaration()`，也可给战力方案的 `Owner` 或 `RegisterFactor` 的第四个参数传入同一声明。未能匹配模组声明的注册使用程序集名称。
- 榜单可通过 `RankingBoard.RowLayout` 指定头像、名次和自动补列的默认显示方式，玩家可在「行内容」覆盖默认值。字段可返回 `RankingValue.Progress` 绘制进度条，或返回 `RankingValue.WithIcon` 显示单元格图标。按境界及境界内经验排序可用 `RankingValue.OrderedChoice`，区间筛选仍使用境界本身。
- `RankingRegistry.RegisterGroup` 接收 `RankingGroup`。用模组前缀 ID 标识分组，`Name` 可用名称或本地化键。`Order` 越小越靠前，省略时为 1000。重名分组以 ID 区分，重复 ID 注册返回 `false`，空分组会隐藏。
- `RankingRegistry.RegisterBoard` 接收 `RankingBoard`。指定来源、榜单 ID、默认列与排序，`GroupID` 可指向自建分组或 `RankingGroupIds` 中的现有分组。组内 `Order` 越小越靠前，省略时按注册顺序追加。原版组内榜单按 100、200、300 排列，例如指定 `RankingGroupIds.CharactersAndEquipment` 和 `Order = 150` 可插在人物榜和装备榜之间。旧模组仍可使用 `Category`。目标组暂不可用时，榜单会使用旧分组或出现在「模组榜单」，目标组注册后在界面刷新时归入该组。同一个来源可注册多个榜单。
- `RankingPowerProfiles.RegisterFactor` 注册可用于人物榜的战力因子。`Register` 注册带版本的战力方案，计算时可以调用 `ReadFactor`。每个方案版本都是人物榜中的排序关键字。启用 `RecordPeaks` 后，刷新人物榜并计算该方案的分数时会记录前 100 个采样峰值，按方案和版本保存。

## 接入标准单体战力

模组可在主线程调用 `RankingRegistry.RegisterCombatProvider`，用自身的命名空间给接入方提供稳定 ID。通过已有的 `GodTools.Rankings.Registry/v1` 槽可在运行时发现注册器。用共有库或运行时绑定时传入模组自己的 `GetDeclaration()` 作为 `Owner`。`Read` 刷新时读取一个单位的技能和资源。返回 `true` 表示由该提供方接管自己模组对这个单位的兼容输入，返回 `false` 则保留该模组的内置适配。其他模组仍可为同一个单位各自提供能力。

```csharp
RankingRegistry.RegisterCombatProvider(new RankingCombatProvider
{
    ID = "example:spellcasting",
    Name = "示例法术",
    Owner = GetDeclaration(),
    Read = (actor, data) =>
    {
        if (!TryGetSpellcasting(actor, out var caster)) return false;
        const string mana = "example:mana";
        data.AddResource(mana, caster.Capacity, caster.RegenPerSecond, caster.InitialMana);
        data.AddSkill(new RankingCombatSkill
        {
            ID = "arc",
            Amount = caster.ArcDamage,
            Range = 12,
            Cost = 8,
            ResourceID = mana,
            RecoverySeconds = 0.5,
            CooldownSeconds = 3,
            When = context => context.HealthFraction <= 0.7 && context.Resource(mana) >= 8
        });
        return true;
    }
});
```

- 用 `AddResource` 描述容量、每秒恢复量和起始值。省略起始值时按满资源试算。多项技能通过 `ResourceID` 共用一个池，池只声明一次，其他提供方引用同一个 ID 即可。资源在每场试算中重新初始化。
- 主动技能共用行动间隔，可额外声明独立冷却和次数上限。伤害技能计入对手护甲。治疗量以生命值计算，最多恢复至满血。`IncomingDamage` 每 0.25 秒检查受伤，支持反击、治疗和按比例减免本次试算伤害，可用冷却、次数或消耗限制。概率按期望效果折算，触发时支付完整成本。
- `When` 使用模拟时间、双方血量比例、距离、对手类型、当步伤害和模拟资源。条件应只读取当步模拟数据并返回布尔值。试算从弱到强取首个采样失败区间评定条件技能，避免只在某个高档对手触发的能力直接跨过前面的失败档位。复杂连招、范围战、召唤和控制链仍需模组提供合适的等效数据。可用 `AddNote` 在详情中说明估算覆盖范围。

总览缓存、榜单记录和字段类型可用 [OverviewSnapshots](../Tests/Rankings/OverviewSnapshots.csx) 验证。实机验收使用隔离 WorldBox 和 DebugToolbox 的 [UnifiedRankings](../Tests/Rankings/UnifiedRankings.csx)。Meta 榜单的旗帜、详情和筛选可用 [MetaRankings](../Tests/Rankings/MetaRankings.csx) 验证。启用 Cultiway 后可另外运行 [CultiwayRankings](../Tests/Rankings/CultiwayRankings.csx)。战力注册和字段元数据可用 [CombatProvider](../Tests/Rankings/CombatProvider.csx) 验证，启用 Cultiway 和 CombatGods 后还可运行 [StandardDuelPower](../Tests/Rankings/StandardDuelPower.csx) 对照实际模组样本。

## 接入角色保存

模组可调用 `CreatureSaveExtensions.Register(id, version, capture, restore)`。使用稳定的命名空间 ID（如 `my-mod:training`）和正整数版本号。`capture(Actor)` 返回该模组的 `JToken`，返回 `null` 表示角色没有此数据。`restore(Actor, int, JToken)` 在角色和原版装备载入后执行，参数包含新角色、当初保存的版本及独立的 JSON 副本。模组可在恢复时绑定新角色 ID，并读取已有的载荷版本。没有注册处理器的载荷会保留在原来的存档记录里。按可选依赖接入时，可从 `AppDomain.CurrentDomain.GetData("GodTools.CreatureSaveExtensions/v1")` 获取接口类型。

## 扩展世界脚本

通过 `GodTools.Features.WorldScript.WorldScriptRegistry.RegisterAction` 或 `RegisterCondition` 注册模组自己的动作和条件。使用带模组前缀的唯一 ID，设置 `AllowedTargets`、`Parameters` 和显示名，再提供 `Execute` 或 `Evaluate`。注册成功后，世界脚本编辑器会在对应对象的选择器里列出它。

- 动作可以通过 `RecordChange` 记录实际变化量，通过 `SkipAction` 说明跳过原因。能无副作用估算数量的动作可以提供 `EstimateChange`。
- 创建对象的动作可以声明 `OutputKind`，再调用 `RecordOutput`，让后续步骤引用这些对象。包含模组扩展的脚本包需要在装有对应模组的世界中启用。
- 脚本包存放在游戏数据目录下的 `world_script_packages` 中。导入会生成停用草稿。包内的延时复查引用会自动改绑到导入的脚本。
